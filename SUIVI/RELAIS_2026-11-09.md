## 2. Défaut trouvé et corrigé (D-19, à consigner dans DECISIONS.md)

Les bootstraps de l'EM de l'étape des prix alignaient les réplicats sur les seules moyennes (hongrois sur
`cdist(mu)`). C'est le cas de l'unité d'alerte et des 300 unités de couverture (HP6).

- Le modèle de référence a K = 2 composantes, aux moyennes voisines : tension 10,5 % (maïs +0,11), calme 89,5 %.
- Dans 47 réplicats sur 200, l'alignement prenait la grosse composante pour la tension.
- Diagnostic : `diag_alerte_em.py`, dans le dossier de travail de la session précédente. Résultats :

| Alignement | Largeur IC90 moyenne de P(tension), EM-BIC | IC contenant 0,5 |
|---|---|---|
| Moyennes (ancien code) | 0,94 | 100 % |
| Responsabilités (nouveau code, identique au démarrage chaud dans 200 cas sur 200) | 0,10 | 7 % |
| VB-emp, pour comparaison | 0,08 | 6 % |

- **Correctif** : `comparaison.aligner_bootstrap`, un appariement hongrois sur le recouvrement des responsabilités
  calculées sur les données d'origine. Il est utilisé dans `etape_prix.unite_couverture` et `unite_alerte`.
- **Test** : `tests/test_alignement_bootstrap.py`. La suite complète passe (102 tests).
- **Conséquence** : la couverture du bootstrap EM-BIC (66 % pour pi, 82 % pour mu) et la décision HP6-diff
  « VB < EM-BIC » (RH3) étaient sans doute gonflées. La couverture du VB (22 % et 64 %) n'est pas touchée : les
  résumés FR et EN restent justes.
- **Non refait** : `calibrage.py:821` (pilote de `n_bootstrap_modele`) utilise encore l'ancien alignement. B = 1 000
  reste prudent : le noter dans D-19 sans refaire le calibrage.
- `.gitattributes` (`data/** -text`) : sans lui, Git sous Windows ajoute des CRLF au CSV des prix et
  l'empreinte SHA-256 vérifiée par `donnees.py` échoue.
